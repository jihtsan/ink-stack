# Codex 额度 · codex-usage

状态：已实现首版 manifest、配置 schema、连接 schema、默认配置、纯归一化、SVG 绘制和 fixtures；真实账号读取由服务端 connector 提供，本机只读核对证据见 [Codex 集成文档](../../../../docs/codex-integration.md)。支持尺寸为 **2 列 × 4 行**；第一版仅支持此尺寸，组件声明最小像素区域为 220×330。

## 显示内容

- Codex 标题、用户自定义账号别名及当前额度分组名称。
- 所选额度分组返回的窗口：窗口时长、剩余百分比和黑白进度条。
- 各窗口的重置时间，按看板时区显示。
- 数据实际采集时间；过期、未登录、读取失败等状态。

布局示意（仅为假数据，不是当前账号数据）：

```text
┌──────────────────────┐
│ CODEX · 工作账号     │
│                      │
│ 5 小时窗口          │
│ 剩余 72%            │
│ ███████░░░          │
│ 重置 09-04 18:30    │
│                      │
│ 7 天窗口            │
│ 剩余 41%            │
│ ████░░░░░░          │
│ 重置 09-07 10:00    │
│                      │
│ 采集于 09-04 16:20  │
└──────────────────────┘
```

窗口名称由实际返回时长生成，不默认存在 5 小时或 7 天窗口。单窗口时重新排布；缺失窗口不能画成 0%。两个额度分组需要两个组件实例，不混合计算“总剩余”。

PNG 是采集时刻的快照。优先显示绝对重置时间；跨过重置时间但尚未重新采集时显示待更新，不能自行把额度改为 100%。

## 计划文件

```text
codex-usage/
├── README.md
├── manifest.json       # type、版本，默认及支持尺寸均为 2×4
├── config.schema.json  # 别名、数据源引用、额度分组、低余额阈值
├── defaults.json
├── server.ts           # 后端读取额度快照，转换为组件数据
├── normalize.ts        # 上游字段到显示字段的纯转换
├── render.ts           # 2×4 布局、黑白额度条、状态文字
└── fixtures/           # 正常、单窗口、多分组、耗尽、未登录、过期等
```

通用进程连接和凭据管理归后端平台；组件内部保存额度字段适配及展示逻辑。浏览器只读取公共元数据，不导入 server.ts。

当前归一化输入对齐 `apps/server/src/connectors/codex-app-server.ts`：

```ts
type CodexRateLimitBucket = {
  limitId: string;
  limitName: string | null;
  primary: CodexQuotaWindow | null;
  secondary: CodexQuotaWindow | null;
  rateLimitReachedType: string | null;
};
```

`rateLimits` 是 legacy 单 bucket，`rateLimitsByLimitId` 是 bucket map。不存在的分组会显示缺失，不会把 legacy bucket 改写成用户选择的 ID。

## 数据来源

优先在已具备合适 Codex 登录态的主机上，通过官方 Codex App Server 的 `account/rateLimits/read` 读取。实施时验证本机版本、初始化握手和认证条件，不把它当成可直接访问的公共 REST URL。

官方文档说明该接口提供 ChatGPT 额度，包含已用比例、窗口时长、重置时间以及可选的多额度分组。这里只消费这些只读数据，不通过本地 token 历史估算账号剩余额度，也不触发额度重置。

如 InkStack 与 Codex 登录环境位于不同主机，需在实施前选择：在服务主机配置合适登录环境，或由登录主机上的采集器发送最小额度快照。后一种方式需要额外采集器、认证与新鲜度验证，不能假定 NAS 或云端自动读到个人电脑的额度。

引用配置保存数据源 ID，不保存账号密码、访问令牌或认证文件内容。默认使用自定义别名，不把真实邮箱绘制到图片或写入样例。

组件设置提供已有本机连接与额度分组选择，不提供用普通 API key 替代 Codex 登录的字段。将来远程采集器接入后的入口和认证令牌属于采集器连接，与 Codex 账号凭据分开。通用字段与保存规则见 [组件连接配置](../../../../docs/component-connections.md)。

## 显示规则

组件保留数据源范围、额度分组 ID、采集时间，以及每个窗口的时长、已用比例和重置时间。已用比例有效时，剩余比例为 `clamp(100 - usedPercent, 0, 100)`。缺失或非数值保持未知状态。

存在多分组视图时优先读取它；兼容旧单分组视图。按稳定分组 ID 选择，选择的分组消失时明确提示，不静默切换成另一个分组。legacy 单分组只使用上游 `limitId`，不凭名称猜测具体模型归属。

只把时长确认为 300 分钟、10080 分钟的窗口分别显示为 5 小时、7 天；其他时长按真实值展示，未知时长显示“额度窗口”。reset 时间未知显示“重置时间未知”。

`observedAt` 必须来自服务端 connector 或调用方。归一化不会用当前时间伪造采集时间；非法或未来采集时间不会显示为新鲜状态。超出最大过期时间后，窗口数值隐藏为未知，避免把旧百分比伪装成当前额度。

普通配额与额外付费额度等字段不合并。第一版专注窗口剩余比例和重置时间，不显示金额、不计算可用请求数。

## 采集与异常

初始建议每 10 分钟采集一次，和看板生成任务协调；手动更新应合并并限频。同账号和分组的多个实例复用一次采集，不在每次 Kindle 请求 PNG 时调用上游。

- 新鲜：显示采集结果。
- 网络错误：保留最近有效值并标注过期与实际采集时间，不把缓存时间改成当前时间。
- 超过配置的最大过期时间：数值显示未知，提示数据未更新。
- 未登录或认证失效：显示需要登录，后台提供修复提示，不自动发起登录。
- API-key-only 或其他不提供此类额度的来源：显示不支持，不伪造百分比。
- 配额耗尽：0% 是有效数据，显示额度已耗尽。
- primary 或 secondary 任一有效窗口为 0% 时，账号可能已受限，因此状态显示为耗尽。
- 字段或整个分组缺失：显示不可用，与额度耗尽区分。

低余额默认阈值建议为 20%，可配置。用文字和边框表达提醒，不依赖颜色；该阈值是产品配置，不是上游额度规则。

## 验收

1. 在 4×6 网格中可占据 2×4 区域；不支持的跨度被拒绝。
2. 假数据中已用 25% 正确显示剩余 75%；已用 100% 显示剩余 0%。
3. 缺失值、缺失窗口、未知时长和未知重置时间均不转换为虚假的零或默认值。
4. 多分组选择与旧单分组兼容，切换来源不会展示上个账号的缓存。
5. 登录失效、超时、过期和额度耗尽具有不同状态；PNG 生成失败保留旧图。
6. 过了重置时刻但未拿到新数据，不自动推断额度恢复。
7. 中文、较长别名、绝对重置时间和两条额度条在实际 2×4 像素区域内可读。
8. 真实读取结果与同账号、同分组、相近时刻的 Codex 显示核对；完成后才宣称额度集成可用。
