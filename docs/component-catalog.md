# InkStack 组件清单与接入规划

状态：首版软件已实现并进入本地验收（2026-09-05）。下文保留原设计约定；实际交付范围、命令和验证证据以 [验收记录](verification.md) 与 [部署说明](deployment.md) 为准，Kindle 实机仍待验证。

## 设计原则

InkStack 的看板按网格放置小组件，类似 iPhone 小组件。每个组件实例占用整数个格子，服务端根据屏幕尺寸、列数、行数、外边距和间距计算最终像素区域，再把整张看板输出为 PNG。

建议第一版看板使用 `4 x 6` 网格。组件尺寸使用 `columns x rows` 表达，例如 `2 x 1` 表示宽 2 列、高 1 行。同一组件可以支持多个尺寸；尺寸变化时应重新组织信息层级，而不是简单缩放同一张画面。

设备端只需要获取已发布 PNG。组件类型、配置和数据获取都由 InkStack 服务端负责，Kindle 不需要理解组件。

## 目录约定

每一种组件放在独立文件夹中：

```text
packages/widgets/src/
  text/
  date/
  weather/
  todo/
  codex-usage/
  calendar/
  image/
```

每个组件目录包含定义、配置校验和渲染实现；需要取数或资源准备的组件增加后端适配文件。具体文件职责见 [组件开发约定](widgets.md)。当前通过源码注册组件，不做在线插件安装，也不运行用户上传代码。

## 首版组件

首版先用本地组件验证“网页配置 -> 预览 -> 发布 PNG -> Kindle 获取”的闭环，同时包含用户要求的 Codex 额度组件，作为优先接入的数据型组件；真实额度读取需单独验证。

| type | 路径 | 用途 | 建议尺寸 | 数据来源 |
| --- | --- | --- | --- | --- |
| `text` | `packages/widgets/src/text/` | 固定文字、备注、标题、提示语 | `2 x 1`, `4 x 1`, `2 x 2`, `4 x 2` | 本地配置 |
| `date` | `packages/widgets/src/date/` | 日期和星期 | `2 x 1`, `4 x 1`, `2 x 2` | 服务端渲染时间与本地配置 |
| `todo` | `packages/widgets/src/todo/` | 手动维护的待办列表 | `2 x 2`, `2 x 4`, `4 x 2`, `4 x 3` | 本地配置 |
| `codex-usage` | `packages/widgets/src/codex-usage/` | Codex 额度剩余比例、重置时间、采集状态 | **`2 x 4`** | 经认证的 Codex App Server 额度快照 |

### text

`text` 用来显示固定文字，适合做看板标题、短句、提醒或分区说明。

尺寸行为：

| 尺寸 | 内容组织 |
| --- | --- |
| `2 x 1` | 单行或两行短文本，强调可读性 |
| `4 x 1` | 横向标题，可显示副标题或更新时间 |
| `2 x 2` | 多行文本，适合备注或短说明 |
| `4 x 2` | 大段摘要，可显示标题、正文和小号辅助信息 |

配置项：

- 文本内容
- 字号级别
- 对齐方式
- 是否显示边框或背景

刷新触发：配置变更并发布后刷新；没有外部数据更新。

空、过期和错误行为：内容为空时显示空白占位或隐藏文本区域；文本过长时裁剪或按组件规则换行，不能溢出格子。

### date

`date` 用来显示当前日期和星期。农历或节气属于将来按需扩展，不在首版配置表单中预留无效开关。它不是实时分钟时钟；显示精度必须与服务端生成频率和 Kindle 下载频率匹配。

尺寸行为：

| 尺寸 | 内容组织 |
| --- | --- |
| `2 x 1` | 月日和星期 |
| `4 x 1` | 完整日期、星期和简短副信息 |
| `2 x 2` | 大号日期，附带月份、星期或本地日历提示 |

配置项：

- 日期格式
- 时区默认继承看板配置；首版不单独覆盖
- 是否显示星期

数据来源：平台传入的本次固定渲染时间、看板时区和本地配置。不得承诺分钟级实时更新。

刷新触发：服务端生成图片时重新计算。建议按天或按用户设置的图片生成周期更新。

空、过期和错误行为：服务端时间不可用时不发布新图；保留上一张有效图片。

### todo

`todo` 用来显示用户在配置台手动维护的任务列表。第一版不接入第三方待办服务。

尺寸行为：

| 尺寸 | 内容组织 |
| --- | --- |
| `2 x 2` | 显示标题和少量短待办，数量由实际区域、字号和文本长度决定 |
| `2 x 4` | 竖向列表，适合较多任务 |
| `4 x 2` | 双列或横向摘要，适合分组任务 |
| `4 x 3` | 标题、分组和更多列表项 |

配置项：

- 标题
- 待办条目
- 完成状态
- 排序方式
- 最大显示数量

数据来源：本地配置。

刷新触发：待办配置变更并发布后刷新；没有远程同步。

空、过期和错误行为：没有待办时显示空状态或隐藏列表；条目过多时按最大显示数量截断，并可显示剩余数量。

### codex-usage

首版支持 2 列 × 4 行的竖向卡片。顶部显示 Codex 和自定义账号别名，中间显示所选额度分组的窗口剩余比例、进度条和绝对重置时间，底部显示采集时间和异常状态。

窗口名称和数量遵循实际数据，不写死为“5 小时/每周”。配置包括数据源引用、额度分组和低余额提醒阈值。不同分组不混算；未登录、数据缺失、过期和实际耗尽分开显示。

服务端使用官方只读额度接口；不以 token 使用记录推算剩余额度。默认建议每 10 分钟采集，多个实例复用采集结果。跨主机部署的数据采集方式需在实施前确认。

详细文件、显示规则和验收见 [Codex 额度组件](../packages/widgets/src/codex-usage/README.md)。

## 已接入组件契约与平台待办

以下组件已经完成 catalog、配置校验、纯 SVG 绘制和服务端适配契约，并已接入编辑器；外部凭据、资源权限、调度和持久化仍属于平台待办。

| type | 路径 | 用途 | 建议尺寸 | 数据来源 |
| --- | --- | --- | --- | --- |
| `weather` | `packages/widgets/src/weather/` | 天气概况、温度、天气趋势 | `2 x 2`, `4 x 2` | 和风天气服务端连接；密钥由服务端保存 |
| `calendar` | `packages/widgets/src/calendar/` | 月历、日期标记、日程摘要 | `4 x 2`, `4 x 3`, `4 x 4` | 本地月历 + Google Calendar OAuth 适配契约 |
| `image` | `packages/widgets/src/image/` | 本地图片、二维码、封面图 | `2 x 2`, `4 x 2`, `4 x 3`, `4 x 4` | 服务端登记的相册或目录；不接受远程 URL |

### weather

`weather` 用来显示当前天气，以及可切换的每日、逐小时或空气质量扩展信息。组件已定义和风天气连接 schema、位置/单位配置、缓存状态和过期提示；应用层已提供受控 HTTP transport、连接管理、调度和缓存持久化。当前默认使用 QWeather v1 经纬度接口，真实 Host/密钥仍由部署者配置。

尺寸行为：

| 尺寸 | 内容组织 |
| --- | --- |
| `2 x 2` | 当前温度、天气状态、城市和更新时间 |
| `4 x 2` | 当前天气 + 每日预报、逐小时预报或空气质量（由 `forecastMode` 选择） |

配置项：

- 城市或位置
- 单位
- 数据源适配器
- 缓存有效期
- 扩展信息模式：每日预报、逐小时预报或空气质量
- 是否显示更新时间

数据来源：和风天气服务端连接。API Host、认证方式和秘密引用只存在服务端连接记录，不能写入公开看板配置。

刷新触发：按服务端数据刷新计划更新；设备请求图片时不直接调用天气接口。

空、过期和错误行为：可接受期限内优先显示最后有效数据并标注更新时间；首次没有有效数据或超出最大过期时间时显示不可用状态。正常绘制的过期或不可用状态可以作为新图发布；整个画面渲染失败时保留上一张有效 PNG。

### calendar

`calendar` 用来显示月历、日期标记和日程摘要。组件支持本地月历和 Google 事件适配契约；应用层已接入 OAuth 路由、加密 token、日历列表和事件 HTTP 请求，真实用户授权仍需部署者完成。

尺寸行为：

| 尺寸 | 内容组织 |
| --- | --- |
| `4 x 2` | 紧凑月历，强调今天 |
| `4 x 3` | 完整月历，显示周标题和少量标记 |
| `4 x 4` | 月历加下方事件摘要 |

配置项：

- 月历月份来源：当前月或指定月
- 周起始日
- 是否显示周标题
- 本地日期标记
- Google 日历连接引用、日历 ID、事件范围和显示数量

数据来源：本地月历规则和可选的 Google Calendar 服务端快照。未连接或授权失败时保留月历，并单独显示日程不可用状态。

刷新触发：服务端生成图片时根据日期和配置计算；外部日程接入后按服务端同步计划更新。

空、过期和错误行为：本地月历通常不应为空；外部日程失败时继续显示月历，并把日程区显示为过期或不可用。

### image

`image` 用来显示平台管理的本地图片，例如二维码、封面图或静态海报。组件已定义相册/目录引用、受控扫描、随机或顺序轮换和 PNG 解码；应用层已接入相册管理、上传 API、扫描列表、选择状态和定时采集。

尺寸行为：

| 尺寸 | 内容组织 |
| --- | --- |
| `2 x 2` | 小型图片或二维码；格子不保证正方形，二维码保留原比例及静区 |
| `4 x 2` | 横图或带标题的图片 |
| `4 x 3` | 大图展示，适合封面和海报 |
| `4 x 4` | 重点图片区域，可保留说明文字 |

配置项：

- 本地图片文件引用
- 裁剪方式
- 黑白转换方式
- 是否显示标题
- 边框和留白

数据来源：服务端登记的相册或目录版本。服务器路径不进入公开配置；不支持远程 URL。

刷新触发：图片文件或配置变更并发布后刷新。

空、过期和错误行为：图片缺失或解码失败时绘制明确不可用状态；不得发布损坏的 PNG。资源上传和引用切换由平台管理，新增资源失败不替换已有有效资源。

## 布局示例

目标示例为 `4 x 6` 网格：

```text
row 0: date     4 x 1
row 1: weather  2 x 2, col 0
row 1: todo     2 x 2, col 2
row 3: calendar 4 x 3
```

这是组件已注册后的布局示例；天气与日历在未配置外部连接时仍显示明确的未连接状态。布局模型可直接使用这些组件的默认配置预览。

增加 Codex 的首版布局示例：4×6 网格中，日期占 (0,0,4,1)，Codex 额度占 (0,1,2,4)，待办占 (2,1,2,4)，文字占 (0,5,4,1)。四个区域无重叠且填满 24 个格子。

## 组件验收点

- 每个组件都有独立目录：`packages/widgets/src/<type>/`。
- 每个组件声明稳定 `type`、名称、默认配置、支持尺寸和配置校验规则。
- 组件实例只能占用整数格子，不能越界或重叠。
- 同一组件在不同尺寸下重新组织信息，不只是等比缩放。
- 渲染结果在目标格子内可读，长文本和空数据都有明确行为。
- 数据获取与渲染分开；组件渲染时不直接访问网络。
- 数据型组件有超时、缓存、过期和首次失败行为。
- 数据失败按组件规则显示可接受的旧数据或不可用状态；画面渲染失败不能覆盖上一张已发布有效 PNG。
