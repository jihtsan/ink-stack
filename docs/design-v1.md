# InkStack 网格组件设计与实施规划

状态：首版软件已实现并进入本地验收（2026-09-05）。下文保留原设计约定；实际交付范围、命令和验证证据以 [验收记录](verification.md) 与 [部署说明](deployment.md) 为准，Kindle 实机仍待验证。

## 需求与边界

InkStack 的设备端交付物是通过稳定 HTTP 地址获取的 PNG。平台负责组件、布局、配置、数据和图片发布；kndl-online-screensaver 负责 Kindle 上的取图、显示和休眠唤醒。

第一版按单用户、单看板、一个目标屏幕设计，允许添加多个组件实例。看板按列数×行数划分，组件占整数格子并声明支持的尺寸。每一种组件的代码与配置集中在独立文件夹，通过源码注册。后续扩展设备数量时保留同一图片协议。

首版组件包括文字、日期、手动待办，以及用户要求的 **2 列 × 4 行 Codex 额度组件**。Codex 是优先接入的数据型组件；显示真实额度窗口与重置时间，具体接入验证见 [组件说明](../packages/widgets/src/codex-usage/README.md)。

仓库现已包含首版可运行应用代码。现有边界见 [架构草案](architecture.md)、[组件开发约定](widgets.md) 与 [路线图](roadmap.md)。

详细规划按职责拆分：[网格布局和编辑器](grid-layout.md)、[组件清单](component-catalog.md)、[文件结构](project-structure.md)。

## 模块设计

| 模块 | 现有目录 | 第一版职责 |
| --- | --- | --- |
| 编辑器 | `apps/web` | 组件库、网格吸附、尺寸选择、参数表单、预览、发布 |
| 配置服务 | `apps/server` | 保存草稿和已发布配置、校验数据、提供操作状态 |
| 组件注册表 | `packages/widgets` | 一组件一目录；公共元数据和后端执行分别注册 |
| 数据与渲染服务 | `apps/server` | 获取组件数据、合成画面、转换 PNG、发布文件 |
| 共享契约 | `packages/shared` | 看板、组件实例、屏幕规格、发布状态和网格纯函数 |
| 设备接入 | `devices/kindle` | 生成配置说明、验证上游客户端兼容性 |

初期部署为一个后端进程，同时提供构建后的前端静态资源。模块是代码边界，不拆成多个网络服务。不引入消息队列或独立任务平台。

## 三个核心模型

### 看板 Dashboard

包含 ID、名称、配置版本、时区、屏幕宽高、背景、网格规格和组件实例列表。网格规格包括 columns、rows、外边距和横竖间距。宽高按最终图片像素定义；横竖屏调整要重新检查布局，设备端额外旋转仅在实机需要时设置，避免重复旋转。

同一看板分别保存草稿和已发布配置。后台定时生成只使用已发布配置，不让未完成编辑出现在设备上。

### 组件定义与组件实例

组件定义描述一种能力；实例是用户放进看板的具体组件。同一种组件可重复添加。

定义包括 `type`、`version`、`configVersion`、名称、支持尺寸、默认尺寸、默认配置、配置校验、可选数据获取函数和渲染函数。

实例包括 `id`、`type`、`configVersion`、`config`、`column`、`row`、`columnSpan`、`rowSpan`。坐标从 0 开始，跨度是正整数。限制边界、碰撞、支持尺寸和文本溢出；允许留白。像素矩形由共享网格函数计算，不作为第二套位置字段保存。

渲染函数接收已经取得的数据、组件区域、固定的本次渲染时间、时区和字体资源。函数中不自行访问网络。组件定义中的外部密钥通过后端凭据引用提供，不写入公开配置。

用户可在组件设置中填写适配器支持的服务入口、API 密钥等连接参数，并测试、新建或复用连接。入口设置按版本保存，密钥仅写入服务端；看板保存连接 ID/版本，详见 [组件连接配置](component-connections.md)。

### 已发布图片 Snapshot

包含看板 ID、配置修订号、图片路径、内容摘要、宽高、生成时间和数据状态。摘要从最终 PNG 字节计算，不能仅使用当前时间。

设备首次接入只需要图片 URL 和刷新日程，不要求配对、心跳或专用 API 客户端。

## 用户流程

1. 设置屏幕实际宽高及网格行列数，从组件库添加文字组件。
2. 编辑文字，通过吸附拖动和支持尺寸选项调整布局，保存草稿。
3. 点击预览，服务端用草稿生成临时 PNG，前端展示该图片。
4. 点击发布，服务端从指定草稿修订生成图片，成功后切换已发布配置及图片。
5. 复制稳定图片地址，配置到 Kindle 客户端。

保存草稿不改变设备图片；预览不发布；发布失败保留上一版本。状态分别表达“图片生成成功”和“设备最近请求时间”，没有设备回报时不显示“设备已刷新成功”。

内部开发先用固定网格配置验证首张图片；第一版交付包含吸附拖动和尺寸选择。保留格子位置表单与键盘操作作为辅助。布局冲突时回退操作，不自动覆盖或挤开其他组件。

## 组件如何生成图片

推荐起点：组件生成受控 SVG 元素 → 合成整张 SVG → resvg 转 PNG → 灰度处理、白底合成和尺寸校验 → 发布。

理由：首期以文字、线条和信息卡片为主；这一方案无需在生产服务运行浏览器。文本换行、中文字体、布局和裁剪需要显式实现，不提供任意 HTML/CSS 的兼容承诺。

备选：React/HTML/CSS 页面通过 Playwright 截图输出 PNG。若主要目标是直接复用网页组件和复杂 CSS，可优先选择这一方案，但需要部署浏览器，并管理截图尺寸、字体加载及渲染就绪状态。

第一版只实现一种渲染路径。无论选择哪种，设备图片 URL 保持不变。开发前用包含中文、长文本和简单图表的固定样例验证选定路径。

字体随部署固定并记录版本；预览以服务端实际 PNG 为准。SVG 文本经转义，组件不能通过 SVG 任意加载远程资源或本地文件。

## PNG 分发契约

建议设备接口：`GET /display/:displayToken.png`，使用独立随机只读令牌，访问边界见 [技术架构](architecture.md)。

- 成功返回 `200`、`Content-Type: image/png` 和匹配目标分辨率的、不透明灰度 PNG。
- 返回基于已发布图片字节的强 ETag；命中的 `If-None-Match` 返回 `304`，不返回图片正文。
- 使用要求重新校验的缓存策略，例如 `Cache-Control: private, no-cache`，避免中间缓存长期提供旧图。
- 图片接口只读现有发布结果，不在每次设备请求时访问天气 API 或重新渲染。
- 看板不存在返回 `404`；存在但尚无有效图片返回明确的不可用响应，例如 `503`，不能把 HTML 错误页当作 PNG 返回。
- 图片尺寸、灰度格式和客户端缓存行为在选定 Kindle 上实测确认。

管理接口负责组件列表、草稿保存、预览和发布，单独执行管理身份校验。PNG 接口的鉴权必须与选定上游客户端实际支持的方式匹配，接入前确认；不假设 Kindle 已支持自定义请求头。初期部署目标为可信局域网，不将未完成访问控制的管理界面发布到公网。

## 刷新、发布和存储

人工发布立即生成新图；定时任务仅对已发布看板获取最新数据。建议默认 10 分钟更新一次，可配置。日期或时钟显示的精度应与实际生成及下载间隔一致。

服务端更新日程和 Kindle 取图日程独立。生成完成不代表设备立即更新；正常情况下设备将在下一次取图时看到新图，离线时无此时效保证。

同一看板只执行一个渲染任务；新请求合并为最新待处理修订。发布前核对配置修订，旧任务不得覆盖新配置。相同最终图片内容沿用原 ETag。

先写入完整的新图片，再通过可恢复的发布指针切换版本。配置和图片引用在同一提交中生效；重启后检查已发布引用，保留最近有效版本。不要依赖对正在被读取的 PNG 原地覆盖。

单实例的配置与发布元数据采用 SQLite，建议使用 better-sqlite3 与 SQL 迁移，图片存放本地数据目录；精确依赖及目标平台兼容性在预研中核对。需要备份配置、发布元数据和仍被引用的图片。

网络数据获取设置超时和缓存；失败可使用最后有效数据并标记过期，首次无有效数据则显示不可用状态。整个渲染失败保留旧图片，并在管理台显示错误和旧图片时间。

## 分阶段实施与验收

### A. 组件目录、网格契约与首张图片

在 `packages/shared` 定义看板、网格、组件和屏幕契约及网格纯函数；在 `packages/widgets/src/text` 实现文字组件，分开注册公共元数据与后端代码；在 `apps/server` 完成固定网格配置到 PNG 的输出。

验收：默认配置通过 schema；注册表无重复类型且版本一致；网格位置、跨度、碰撞和余数像素换算正确；给定尺寸输出可解码 PNG；中文无缺字、长文本不越界。用网格边界测试和固定画面样例验证。

### B. 网格编辑与首版组件

在 `apps/web` 实现左侧组件库、网格画布、右侧配置、吸附拖动和支持尺寸调整；在 `packages/widgets/src/date` 与 `todo` 增加日期和手动待办；在 `apps/server` 实现草稿存储、预览和版本发布。

在 `packages/widgets/src/codex-usage` 实现 2×4 额度卡片和纯字段转换，先用明确标记的模拟数据验证正常、单窗口、缺失、过期及耗尽状态。模拟结果不能作为真实集成完成的依据。

验收：一个看板可添加两个同类型实例并分别配置；移动、复制、删除和尺寸选择可用，非法放置回退；删除在当前会话可撤销；前后端都拒绝冲突和不支持尺寸；旧预览响应不覆盖新布局；保存或预览不改变已发布图；发布失败保留旧图；服务重启后恢复草稿和发布状态；旧任务不能覆盖新版本。

### C. 图片服务与 Kindle 接入

在 `apps/server` 完成稳定图片地址、ETag、已发布看板定时更新和异常状态；在 `devices/kindle` 补充选定机型与客户端配置步骤。

优先接入 Codex App Server 的只读额度快照，验证已登录主机与 InkStack 的部署关系。真实窗口时长与分组由上游决定，不推算可用请求数或根据本地 token 总量估计剩余比例；凭据不进入看板配置和 PNG。与同账号、同分组的 Codex 显示核对后完成该组件的数据集成。

验收：设备获取到正确尺寸的 PNG；相同内容条件请求返回 304；未发布看板不返回假 PNG；失败保留有效旧图；完成至少三次设备定时唤醒、取图和显示；断网后保留有效画面，恢复网络后可继续更新；退出客户端能恢复正常阅读。

电源管理通过设备日志和实际行为验证。三轮测试只证明基本连通和唤醒，不足以承诺长期续航；续航需要另外记录至少一昼夜的电量变化和刷新设置。

### D. 扩展数据型与图片组件

在独立目录中增加天气、日历和图片组件。天气先接一个数据源并验证缓存；日历先做本地月历再扩展外部日程；图片先支持平台管理的本地上传。最后按需求评估配置导出、多设备、设备回报及是否 fork 客户端。

验收：按目录约定开发并注册组件即可加入组件库，无需更改 Kindle 图片协议；每种尺寸正确重排内容；外部请求超时后展示可接受的缓存或不可用状态；过期数据显示时间；图片缺失或解码异常不产生损坏的已发布 PNG。

## 主要风险与处理

| 风险 | 处理与验证 |
| --- | --- |
| 中文缺字或预览不一致 | 固定字体；用实际 PNG 预览；检查中文、数字、长文本样例 |
| 上游客户端和设备不兼容 | 开始设备集成前确认型号、固件、linkss 和客户端版本；实机验证 |
| 数据源失败导致画面过期 | 缓存最后有效数据，显示更新时间；失败不覆盖已发布图 |
| 多次发布乱序或重启留下坏引用 | 串行渲染、修订校验、可恢复的发布指针；注入乱序和重启验证 |
| 可配置资源导致意外网络或文件访问 | 数据请求只通过受控适配器，校验目标；不执行用户上传组件代码 |
| 后台误报设备在线或已刷新 | 只显示有证据的请求时间；显示成功需要未来客户端回报 |
| 网格缩小导致配置丢失 | 先模拟并检查所有实例；冲突时拒绝应用，保留原布局 |
| 组件取数代码进入浏览器 | 分离 catalog 与 registry.server；构建时检查导入边界 |

## 实施前需确认的选择

1. 验证推荐的 SVG/resvg + sharp 路径；仅在关键排版验证不通过时重新评估 HTML 截图路线。
2. 实际部署主机、Kindle 型号和固件；这些影响运行包、客户端和访问配置。
3. Codex 登录环境是否与 InkStack 同机；若不同，需要明确采集位置及最小快照的认证传输方式。

软件开发与本地验证已推进；未安装或修改 Kindle 客户端、固件。
