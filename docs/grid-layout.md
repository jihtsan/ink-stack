# 网格布局与编辑器

状态：首版软件已实现并进入本地验收（2026-09-05）。下文保留原设计约定；实际交付范围、命令和验证证据以 [验收记录](verification.md) 与 [部署说明](deployment.md) 为准，Kindle 实机仍待验证。

## 看板定义

网格配置包括 columns、rows、水平/垂直间距和四边外边距。目标屏幕规格保存最终 PNG 宽高。建议起始布局为 4 列 × 6 行，可以改成其他列数和行数；网格不要求正方形，格子也不强制为正方形。

组件保存格子坐标，不保存独立像素位置：

```json
{
  "id": "weather-home",
  "type": "weather",
  "configVersion": 1,
  "column": 0,
  "row": 1,
  "columnSpan": 2,
  "rowSpan": 2,
  "config": { "locationLabel": "示例城市" }
}
```

坐标从 0 开始；跨度是正整数。上述配置仅演示位置字段，天气正式配置以组件 schema 为准。

## 布局规则

1. 组件占据完整矩形，不允许 L 形占用。
2. 移动吸附到网格，禁止重叠、越界以及不支持的跨度。
3. 新增或复制时按从上到下、从左到右查找空位；没有合法空位时提示，不移动或覆盖其他组件。
4. 拖动落点无效时回到原位置，并显示冲突区域；不自动挤开其他组件。
5. 更改尺寸先提供组件声明的尺寸选项，再检查当前位置能否容纳。缩放手柄也只能落在支持尺寸。
6. 允许留白；空区域显示画布背景，不默认填充组件。
7. 删除需要可撤销反馈；首期撤销作用于当前编辑会话，不引入服务端历史版本系统。
8. 修改网格或屏幕方向先模拟布局。发生冲突或无法满足最小像素区域时，不提交变更，保留原配置并列出冲突组件。
9. 前端即时反馈，后端保存和发布时再次校验；不能只信任拖拽 UI。

## 像素换算

采用同一份纯函数供前后端使用，避免分别计算引入偏差。外边距和间距按最终输出像素定义。

设屏幕宽为 W，左右边距为 L/R，列数 C，列间距 g，可分配给列的宽度为：

```text
U = W - L - R - (C - 1) × g
```

第 c 列开始、横跨 s 列的组件：

```text
x     = L + floor(c × U / C) + c × g
width = floor((c + s) × U / C) - floor(c × U / C) + (s - 1) × g
```

高度使用行数和上下边距同理计算。用边界取整分配余数，确保末列/末行准确抵达可用区域边界，不累计误差。U、可用高度及每格实际尺寸都必须为正。

网格间距属于平台；组件内部 padding 属于组件主题。编辑器中的选择框和网格线不进入最终 PNG。

## 编辑器界面

- 左侧：组件库，按类别显示名称和支持尺寸。
- 中间：按设备宽高比例显示画布、网格、组件位置及选中状态。
- 右侧：选中组件的配置、尺寸选项和删除/复制操作；未选中时显示画布设置。
- 顶部：保存草稿、预览最终 PNG、发布和当前操作状态。

拖动时即时显示矩形占位和吸附结果，不必每一帧请求图片生成。拖放结束或配置停止输入后请求新的服务端预览；响应绑定草稿修订号，过期响应不得覆盖较新的预览。

编辑器允许几何位置即时反馈；最终预览使用服务端实际 PNG。键盘方向键按格移动，表单和尺寸按钮也可操作布局，避免只能依赖拖动。

## 验收例子

在 4×6 网格中：日期占 (0,0,4,1)，天气占 (0,1,2,2)，待办占 (2,1,2,2)，日历占 (0,3,4,3)，应合法且填满看板。这是完整组件库就绪后的目标例子，不表示这些组件已实现。

- 两个组件边缘接触但不共用格子，应允许。
- 在已占用区域添加组件，应拒绝并保留原布局。
- 将 2×2 组件移动到第 4 列起点，应拒绝越界。
- 将仅支持 2×2、4×2 的组件改成 3×2，应拒绝。
- 将已用 4 列的看板缩为 3 列，应列出冲突而非丢失组件。
- 使用不能被列数整除的可用宽度，前后端应给出相同像素矩形，并保持边距与间距准确。
- 改动网格后收到旧预览响应，应忽略；预览和保存不会替换已发布图片。

首版 Codex 额度布局例子：日期 (0,0,4,1)、Codex (0,1,2,4)、待办 (2,1,2,4)、文字 (0,5,4,1)，合法且填满 4×6 网格。Codex 的宽度是 2 列、高度是 4 行，不可误写为 4×2。
