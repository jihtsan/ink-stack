# 架构草案

状态：设计草案，尚未实现。

## 目标

让用户通过小组件配置墨水屏内容，并让低功耗客户端定时获取服务端生成的图片。

## 数据流

1. 管理前端提交设备参数、组件配置与布局。
2. 后端校验配置并持久化。
3. 后端为组件获取数据，将数据交给渲染实现。
4. 渲染服务生成与设备尺寸一致的 PNG。
5. 成功后发布新图片；失败时保留最后一张有效图片。
6. Kindle 使用稳定图片地址和条件请求获取更新。

## 模块职责

网页端负责编辑和操作反馈。后端负责可信配置、凭据、数据获取、图片生成及发布。组件模块负责组件定义与渲染。设备客户端负责设备侧的显示、休眠与唤醒。

服务端生成日程与设备下载日程相互独立。HTTP 304 只能减少重复传输；设备是否跳过刷新、是否真正休眠，需要客户端配合并实机验证。

## 首期边界

- 单用户、单设备、单个看板。
- 一个可编辑的文字组件。
- 固定尺寸布局与最终 PNG 预览。
- 配置持久化、稳定图片地址和 ETag。
- 对接现有 Kindle 客户端。

可视化拖拽、多设备、数据型组件、在线组件市场和自动安装设备脚本留待后续阶段。

## 实现前待确定

- 前后端框架、渲染库和配置存储方式。
- 部署环境：局域网主机或云端。
- 管理接口与图片接口的访问控制。
- 目标 Kindle 型号、固件和客户端兼容性。
- 中文字体的选择、打包及许可证。

这些选择应在首个可运行版本中形成实际代码和验证记录，避免仅凭目录结构认定技术选型已完成。
