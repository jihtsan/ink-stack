# 组件开发约定

状态：首版软件已实现并进入本地验收（2026-09-05）。下文保留原设计约定；实际交付范围、命令和验证证据以 [验收记录](verification.md) 与 [部署说明](deployment.md) 为准，Kindle 实机仍待验证。

## 一种组件，一个目录

```text
packages/widgets/src/weather/
├── README.md             # 用途、配置、尺寸、数据来源、开发说明
├── manifest.json         # 类型、版本、名称、支持的格子尺寸
├── config.schema.json    # 配置字段与校验规则
├── connection.schema.json # 可选：服务入口、认证方式、秘密字段定义
├── defaults.json         # 新增实例时使用的默认配置
├── render.ts             # 纯绘制入口
├── server.ts             # 可选：后端数据获取
├── views/                # 可选：尺寸布局差异较大时拆分
│   ├── compact.ts
│   └── wide.ts
└── fixtures/             # 示例配置、模拟数据、空态与错误样例
```

这是目标结构。text、date、todo、codex-usage、calendar、weather、image 目录均已有运行代码；应用层已为天气、Google Calendar 和图片资源提供连接/资源管理、取数与调度接线。小组件不要求每个尺寸建立一个文件；只有布局明显不同时才拆分 views。本地文字、日期、手动待办不需要 server.ts。

## 元数据与实例分开

manifest.json 描述组件类型，包括 type、名称、说明、version、configVersion、支持尺寸和默认尺寸。

尺寸统一使用对象 `{ "columns": 2, "rows": 2 }`；文档中的 2×2 表示宽两列、高两行。默认尺寸必须在支持尺寸列表中。未来可增加最小像素区域限制，避免同样的格子跨度在小屏上变得不可读。

每个看板组件实例保存独立 id、type、configVersion、config，以及 column、row、columnSpan、rowSpan。同一种组件允许多个实例。type 稳定，不因显示名称变更而变化。

组件代码版本与配置版本分别管理。第一版遇到不支持的配置版本或未知类型时，明确报错并阻止发布，不静默删除实例。配置升级策略在首次真实格式变更时补充。

## 配置与编辑

基础表单根据配置 schema 生成，首期只支持需要的字段类型：短文本、长文本、数字、枚举、布尔值及待办事项列表。默认配置需要通过同一套校验。

配置只保存用户意图。例如天气保存城市或经纬度、单位，不把当前温度当作用户配置。组件临时数据、访问密钥和缓存不存进看板 JSON。

复杂自定义编辑器以后按需增加，暂不要求每个组件创建编辑器文件。编辑器 UI 与墨水屏渲染组件是不同职责。

数据型组件可在设置面板内创建或选择连接，填写适配器支持的 API 入口与密钥，并测试连接。connection.schema.json 定义这些字段；看板仅保存连接 ID/版本，密钥通过专用接口写入服务端，保存后不回传原文。共享连接、密钥轮换及私有 URL 的处理见 [组件连接配置](component-connections.md)。

## 运行契约

| 步骤 | 输入 | 输出 | 负责人 |
| --- | --- | --- | --- |
| 配置校验 | 实例配置、配置版本 | 有效配置或字段错误 | 公共契约与组件 schema |
| 数据获取（可选） | 配置、受控请求工具、凭据引用 | 数据、更新时间、有效/过期/不可用状态 | server.ts，仅后端运行 |
| 区域计算 | 网格、屏幕规格、实例跨度 | 像素矩形 | 平台共享网格逻辑 |
| 绘制 | 配置、数据、像素区域、尺寸规格、固定时间与时区、主题 | 当前渲染器接受的绘图内容 | render.ts |
| 图片合成 | 所有组件的绘图结果 | 最终 PNG | 平台渲染服务 |

组件以自身区域左上角为原点绘制。平台负责定位、裁剪、背景、合成和 PNG 输出；组件不能绘制到分配区域之外。

同一次任务共用固定渲染时间与数据快照。render.ts 不发网络请求、不读取任意本地文件，不直接取系统时间，从而保证预览和发布可以复现。

当前推荐 SVG 绘制；实际渲染内容类型和库在实施前确定。第一版只采用一条渲染路径，不同时设计多种插件运行时。

## 多尺寸行为

组件按支持尺寸重排信息，不把小尺寸画面直接拉伸。天气 2×2 展示当前状态，4×2 可增加预报。待办增大后显示更多行。

组件内部处理换行、行数限制、字号下限和“还有 N 项”的提示。平台裁剪只是最后的边界保护，不代替可读性设计。

## 注册与加载

规划三个入口：

- src/catalog.ts：显式注册 manifest、schema、defaults；可供前端使用。
- src/render.ts：浏览器可用的纯绘制导出，复用文字、日期和待办的 render.ts；不包含数据获取或服务端注册。
- src/registry.server.ts：显式注册绘制入口和可选数据适配器；仅后端使用。
- src/_template/：开发说明模板，不注册为可添加组件。

新增组件的步骤是复制模板、实现文件、添加这两个注册记录、验证元数据一致性并重新构建部署。**放入文件夹不等于运行中自动安装**。目录组织解决可维护性，动态安装和热加载是后续独立能力。

不提供同时导出服务端取数代码的通用入口给浏览器，不依赖打包器自动移除敏感代码。构建时验证两份注册表的类型和版本匹配、无重复类型。

## 数据失败与验证

数据获取设置超时、缓存有效期及最大可接受过期时间。可接受的旧数据明确显示时间；无有效数据时显示不可用状态。渲染失败保留上一张已发布图片。

每种组件至少验证默认配置、非法配置、每种声明尺寸、长文本、中文和重复实例。数据型组件还验证空数据、过期数据、取数超时。支持尺寸、示例和配置 schema 必须一致。

上游客户端安装说明见 [Kindle 接入](../devices/kindle/README.md)。添加服务端组件不需要修改 Kindle 的 PNG 下载协议。
